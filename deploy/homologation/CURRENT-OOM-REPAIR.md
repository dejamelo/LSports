## Completed application shutdown with a live container/init

An inspected docker-init is not the whole container. With `ADL_FINALIZE_VERIFIED_SHUTDOWN=1` and a pinned original preparation, the helper lists every container process using Docker's process list (PID, parent, state, executable, namespace PID/RSS/thread metadata). It does not infer Node exit from init RSS or from worker.shutdown/ok. The old container/image ID and the saved distribution Stop remain mandatory.

For an already-requested shutdown with an observed handler completion, the helper verifies no other container can write the feed volume, then records and applies a reversible pause to the old container. This freezes all its processes/threads. Unowned pauses are not taken over. It makes a new root-private original copy of checkpoint, private sidecar and both SQLite databases plus available WAL/SHM; every source/copy hash is checked. It never opens the originals in SQLite. A separate non-root working copy is used for integrity_check, every pending committed row (in ID order), bounded decoder/state replay, sidecar/public serialization and complete fresh-process readback/restore. All raw rows remain in the original inbox and copied DB. No row is deleted or broker-ACKed by the proof. Per-lane counts, sequence, raw hashes, decoded types, memory and persisted-state hash are recorded. This proves local committed-row recoverability, not supplier delivery or a current feed baseline.

The proof has the prepared immutable image, actual node user and4GiB cgroup/2560MiB Node old-space settings. It emits progress every10s and fails with the exact phase/diagnostic. No full inbox array or whole-document stringify is used. On proof failure the original container stays PAUSED with all originals preserved; the receipt identifies the working copy and private attempt log. It does not proceed to a signal. A successful proof can be reused only with matching source, proof-code and output hashes.

Only after successful recovery/readback and unchanged source hashes does one journaled Docker SIGKILL finalize the frozen old container. Docker supports killing a paused container without resuming its business logic; this path was tested locally. A forced exit137 is recorded separately from Docker OOM. The helper confirms exit and original hashes, archives only dead-namespace locks with backup, then continues the existing current-data backup/offline rehearsal/activation/validation gates. It never sends another SIGTERM in this branch. A crash after finalization intent is resolved by verifying the exact stopped container and preserved hashes, rather than repeating the kill.

Local verification: real isolated Docker tests use a synthetic FULL-committed WAL fixture with100 rows per feed, including settlement; all200 rows are replayed and full state hash survives checkpoint/serialization/readback. Omitting WAL is rejected. Original database/WAL/checkpoint hashes remain identical. A separate paused-init/Node test exits137 with OOMKilled=false. Orchestration tests reject failed recovery before finalization and prove no SIGTERM/repeated kill. These are not evidence that the real AWS dataset or process tree already passed; the single resumed executor must verify them before acting.

### Pre-exit round-trip comparison (313,583 pending records)

The proof now writes an expected-state JSONL manifest one entity at a time, ordered by lane and stable identity, before releasing its state. A fresh process restores the complete output and compares every persisted field against that manifest. Object member order is irrelevant; array order, field membership, scalar types, nulls and values remain strict. Only one entity is compared at a time. A mismatch writes `divergence.json` beside the private output and emits lane, hashed identity, field path, types/counts without field values. No termination occurs on mismatch.

### Pre-exit disk headroom
A resumed proof now reuses the authenticated pristine copy without copying it again. Required additional free space remains conservative: 4 × preserved input bytes + 512 MiB when reusing, otherwise 5 × input + 512 MiB. This reserves work-copy, SQLite/replay scratch and output space; it does not assume the replayed projection fits the original checkpoint size.
On shortage the helper inventories allocated bytes of recognized attempt directories only inside the pinned backup. It deletes only unmounted, non-current rehearsal directories whose exact file set and every file hash match frozen source inputs, with no symlinks or hardlinks. Modified SQLite/WAL, original copies, logs, outputs, prepared images and volumes are preserved. No Docker prune. A protected `pre-exit-disk-plan.json` records required/free/missing bytes, destination device, per-copy decisions and minimum additional GiB. Still-insufficient capacity blocks without starting or terminating the worker. Tests cover exact duplicate deletion, modified/active/original preservation, arithmetic and sufficient-space no-cleanup behavior.

### Offline serialization ENOSPC after verified old-container finalization
The offline output is a bind mount under the pinned backup (`projection-rehearsal-<digest>/projection.json`), not the read-only container root. The former preflight counted missing input copies plus 512 MiB only. Before any further restore, the new preflight inventories mount/device/EBS serial mapping and attempt directory allocation. Required free bytes = missing copies + max(8 × source bytes, 2 × failed partial-output bytes) + 4 GiB. This is explicitly a conservative planning estimate, not a measured completed-output size; partial output is only a lower bound. Readback uses the same output read-only in a fresh process and does not require another full disk copy.
Only an unmounted partial projection with no receipt, no verified serialization flag and a matching disk_full failure is unlinkable. Logs, receipts, pristine originals, checkpoint/inbox/WAL, prepared image and all other attempt artifacts remain. The protected offline-rehearsal-disk-plan.json records exact free/required/missing bytes, filesystem capacity, mount source, lsblk serials, consumed attempt bytes, and minimum incremental GiB. gp3 cost is an explicitly conditional us-east-2 $0.08/GiB-month estimate, excluding other charges; physical EBS size/type and any already-provisioned unexpanded filesystem must be verified before changing a volume. No EBS resizing, growpart or prune is automatic. Insufficient capacity stops before a repeat restore. Existing verified container-finalization receipts remain authoritative.

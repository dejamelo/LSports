Installed source currently calls process.availableMemory and takes min(heapLimit-heapUsed,availableMemory). PreMatch streaming scratch budget32MiB*8+64MiB=320MiB; InPlay128MiB SDK response estimate128MiB*8+64MiB=1088MiB. No whole694MB reservation in the PreMatch guard. Public libuv1.51.0 and1.52.1 linux.c implement constrained available memory as min(cgroup memory.high,memory.max)-memory.current, clamped at0 (when cgroup-constrained below host total), including charged file cache. This is not the same as heap margin or host MemAvailable. Runtime headers and source hashes must match before interpreting the installed formula. Source: https://github.com/libuv/libuv/blob/v1.52.1/src/unix/linux.c#L2259 and corresponding v1.51.0 implementation.

Missing evidence is simultaneous cgroup anon/file/dirty/writeback/PSI/OOM counters, memory.high/max, host availability and competing processes/containers. File cache must not automatically be credited as allocatable memory. Another source-level potential contributor is durable ingress processingStats range count/min over all pending inbox rows each report; its current cache/IO impact is not proved by the old totals. No consumer or memory-limit patch is justified from the diagnostic alone.

collect-current-memory-pressure.mjs performs four host-side observations20seconds apart. It does not docker exec another Node into a pressured container, query SQLite, hash/read the large spool, purge anything, change limits, alter distribution or restart workers. It reads only the bounded telemetry prefix, small installed source files, /proc and cgroup controls, Docker metadata and bounded sanitized logs. One dedicated diagnostic flock prevents duplicate collectors; no worker/scheduler locks are changed. Report/progress files are saved on the Mac with mode0600. The worker identity/start is verified each sample. Concurrent container memory is reported per cgroup and host RSS processes separately, not added as independent measurements. Persistence is one shared worker measurement across lanes.

Rates require same session, nondecreasing counters and a fresh metric-window end overlapping the observation. Missing/frozen counters yield unavailable rates rather than a guessed ETA. Oldest age is the worker's separately dated processing metric; ACK means inbox receipt only. This collection intentionally does not rescan the durable inbox while the worker is under pressure. ETA remains withheld until sustained drain and durable checkpoint evidence agree. A memory/sample header or snapshot stat is not validation of a complete snapshot.

Local checks: cgroup fixtures verify max/high accounting, negative clamp and that inactive cache minus dirty/writeback is reported but never added to free memory; collector Node/Python syntax and combined remote source size pass.
